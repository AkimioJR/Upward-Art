# 数字都江堰

> 浩宇套了51层 try-catch，30万行日志零报错，大领导填了40分钟的表单数据全丢了。旭阳现场5分钟把"吞异常事故"包装成"五十道异常拦截闸门"——数字都江堰、四两拨千斤、优雅降级。3800次异常用户零感知，大领导的表从埋点日志里一个字一个字抠回来。王处拍板：《优雅降级弹性架构建设白皮书》。

## 技术真相

一个提交接口，浩宇为了不报错，在外面套了51层 try-catch。每次出错就在外面加一层，套着套着就51层了。甚至把 try-catch 当 if-else 用——"取值写 if 太麻烦了，我直接 try 一下"。结果：30万行日志零 error，看起来系统健康得不行，实际上异常全被吞了。

大领导亲自填了40分钟的申报表，屏幕弹出绿色的"提交成功"，但数据根本没入库。第二天调不出来，20多人坐一屋子查，大领导把王处当众骂了个遍。

旭阳的5分钟救场：①不拆 try-catch，重新定义为"50道异常拦截闸门"；②每层 catch 加异常日志写入"异常静默处置"；③建补录队列，存提交失败的原始数据；④做大屏实时显示"今日化解次数"和"用户感知次数"；⑤找到浩宇3个月前被九如要求删但没删的键盘埋点，从日志里把大领导40分钟敲的1200多个字一个一个抠出来，数据零丢失。

王处现场验证：自己用手机提交垃圾数据，系统不崩，3800次异常全部化解，用户零感知。王处顿悟，搬出都江堰李冰治水的典故——"鱼嘴分水、飞沙堰泄洪、宝瓶口引流"，把51层 try-catch 定性为"数字都江堰"，并记下"优雅降级"这个术语，准备下午汇报用。

最终决策：不修复，写白皮书——《优雅降级弹性架构建设白皮书》，从一个提交接口扩展到全渠道。
